# Manual CSS/JS Includes Removal Changelog

## Date: October 21, 2025

## Summary
Removed pre-built CV HTML files containing hardcoded hashed asset references. These files violated Astro's build principles by including manual `<link>` and `<script>` tags with specific hash values that break across deployments and i18n routes.

## Changes Made

### 1. Removed Pre-built CV HTML Files

#### `public/cv_en/index.html`
- **Issue**: Contained hardcoded references:
  - `<link href=/cv_en/_astro/index.02199620.css rel=stylesheet />`
  - `<link href=/cv_en/_astro/photoswipe.534d0e90.css rel=stylesheet />`
  - `<script src=/cv_en/_astro/hoisted.bd6b0452.js type=module></script>`
- **Action**: File deleted along with entire `public/cv_en/_astro/` directory

#### `public/cv_ru/index.html`
- **Issue**: Contained hardcoded references:
  - `<link href=/cv_ru/_astro/index.3ac188d3.css rel=stylesheet />`
  - `<link href=/cv_ru/_astro/photoswipe.534d0e90.css rel=stylesheet />`
  - `<script src=/cv_ru/_astro/hoisted.c7c071cd.js type=module></script>`
- **Action**: File deleted along with entire `public/cv_ru/_astro/` directory

### 2. Additional Directories Removed
- `public/cv_en/_astro/` - All hashed CSS/JS files
- `public/cv_ru/_astro/` - All hashed CSS/JS files
- `public/cv_en/fonts/` - If present, will be regenerated by Astro
- `public/cv_ru/fonts/` - If present, will be regenerated by Astro

## Impact Analysis

### ✅ Achievements
1. **Zero hardcoded asset references** remain in source code
2. All Astro pages use **automatic asset injection**
3. **No i18n route conflicts** from hardcoded paths
4. **Deployment safety** - assets will be properly hashed on each build

### ⚠️ Breaking Changes
The CV embed functionality at `/en/cv` and `/ru/cv` **will break** because:
- `src/pages/en/cv.astro` embeds `/cv_en/index.html` (now deleted)
- `src/pages/ru/cv.astro` embeds `/cv_ru/index.html` (now deleted)
- `src/components/CvEmbed.astro` references these paths

### 📋 Required Follow-up
You need to either:
1. **Option A**: Rebuild CV pages as native Astro pages
   - Create proper `.astro` pages with component imports
   - Use `<style>` blocks or imported CSS (Astro will auto-inject)
   
2. **Option B**: Set up a proper build pipeline
   - Generate CV HTML during build (not pre-built)
   - Ensure generated HTML doesn't include hardcoded hashes

## Notes

The pre-built CV HTML files were likely generated by an external tool or template system. They contained a complete, minified HTML document with inline styles and hardcoded asset references - a pattern that conflicts with Astro's build philosophy.

Going forward, CV content should be built using:
- Astro components
- Content collections
- Proper CSS imports or `<style>` blocks

This ensures assets are managed by Astro's build system and automatically updated on each deployment.
