1. **Build stage**: Installs dependencies, copies source, runs `npm run build`

Assets are properly configured:
- ✅ Public files in `apps/website/public/` → served from `dist/client/`

## 🚀 Usage

### Development
```bash
cd apps/website
npm run dev
```

### Production Build
```bash
# Build the Docker image
docker build -t website:latest .

# Run the container
docker run -p 3000:3000 \
  -e DECAP_GITHUB_CLIENT_ID="your_client_id" \
  -e DECAP_GITHUB_CLIENT_SECRET="your_secret" \
  website:latest
```

### Using Docker Compose
```bash
# Production deployment
npm run deploy:prod

# View logs
npm run deploy:logs:prod

# Stop
npm run deploy:stop:prod
```

## 🛠️ How It Works

1. **@astrojs/node adapter** generates a standalone Node.js server in `dist/server/entry.mjs`
2. The server serves:
   - SSR pages (rendered on-demand)
   - Static assets from `dist/client/` directory
3. No custom Express/Fastify server needed - the adapter handles everything
4. Assets in `public/` are copied to `dist/client/` during build
5. The standalone server includes all necessary code to serve both SSR and static content

## 📝 Environment Variables

Required for production:
- `PUBLIC_SITE_URL`: Site base URL
- `DECAP_GITHUB_CLIENT_ID`: GitHub OAuth client ID
- `DECAP_GITHUB_CLIENT_SECRET`: GitHub OAuth secret
- `AUTHJS_GITHUB_CLIENT_ID`: Auth.js GitHub client ID
- `AUTHJS_GITHUB_CLIENT_SECRET`: Auth.js GitHub secret

Pass these via Docker build args or runtime environment variables.

## ⚠️ Important Notes

1. **No `astro preview` in production** - use `npm start` (runs `node ./dist/server/entry.mjs`)
2. **Standalone mode** - no `node_modules` needed in runtime container
3. **Static assets** automatically served by the adapter from `dist/client/`
4. **Port 3000** is hardcoded in Dockerfile (configurable via `PORT` env var)
5. **Healthcheck** uses `fetch()` (available in Node 18+)
